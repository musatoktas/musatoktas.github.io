Open source

I measure before I change code.

I contribute to TypeScript and to the tools around it. Most of my fixes start with a slow type check or a crash, a measurement, and a test.

My project

whyts

whyts finds out why a TypeScript project is slow. It runs your own TypeScript compiler with --generateTrace and --extendedDiagnostics, reads the trace, and says where the check is slow. For known patterns it also says why and what to change.

Each finding has a label: measured, observed or review. It does not change your code. You do not need an account, an API key or an LLM.

whyts on GitHub whyts on npm

Try it

npx whyts --project .

To prove that a type change helped, compare two versions with repeated, alternating runs:

npx whyts compare --baseline before/tsconfig.json --candidate after/tsconfig.json

whyts also runs as an MCP server, so a coding agent can measure before and after a type change. The package is whyts-mcp on npm, listed in the MCP Registry as io.github.musatoktas/whyts. MIT license.
